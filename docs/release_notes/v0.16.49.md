# Trinity v0.16.49 – Canvas integriert und Memory kontrollierbar

## Canvas als Bestandteil von Trinity Desktop

- Der macOS- und der Windows-Installer laden Trinity Canvas als fest zur
  Trinity-Version gehörende Repository-Komponente und bauen es automatisch mit.
- Das Canvas-Repository bleibt parallel als Standalone-Anwendung nutzbar; es
  gibt trotzdem nur einen gepflegten Quellcode.
- Trinity startet und beendet Canvas zusammen mit der übrigen Laufzeit.
- Die Classic-Oberfläche enthält einen eigenen Canvas-Reiter.
- Weboberfläche und API verwenden im Normalbetrieb nur noch einen internen
  lokalen Dienst. Anwender müssen keine Portnummer kennen.
- `trinity canvas status|install|update|start|open|stop` steht für Diagnose und
  Wartung zur Verfügung.

## Löschen und Test-Neustart

- Sessions können mitsamt ihren zugehörigen Memory-Einträgen gelöscht werden.
- Eine Session-Zusammenfassung lässt sich separat entfernen.
- Einzelne Memory-Inhalte lassen sich in der Classic-Oberfläche und per CLI
  löschen.
- `trinity memory reset --yes` setzt den operativen Zustand nach einer datierten
  Wiederherstellungskopie zurück.
- Mit `--include-generated --include-canvas` werden zusätzlich erzeugte
  Testmedien und Canvas-Laufzeitdaten gesichert und geleert.
- Vault, RAG-Quellen, Soul, User-Profil und Konfiguration sind ausdrücklich vom
  Reset ausgeschlossen.

## Verständliche Profilnamen

Die sichtbaren Namen lauten nun **Arbeit**, **Privat** und **Development**. Die
internen stabilen Kennungen `BIZ`, `PRIVAT` und `TEST` bleiben für Konfiguration
und Kompatibilität erhalten.
