# v0.16.4 - Pi-Harness fuer BrainVault robuster

## Neu

- Trinitys Pi-Adapter macht dem Pi-Harness jetzt explizit klar, dass er bereits
  im freigegebenen Projektordner gestartet wurde.
- Pi wird angewiesen, im BrainVault-Agentenpool relative Pfade wie `AGENTS.md`
  und `.agents/mail/...` zu verwenden und fragile interne Read-Tools bei
  iCloud-/OneDrive-Pfaden mit Leerzeichen zu vermeiden.
- Pi-Subprozesse erhalten `TRINITY_PROJECT_ALIAS`, `TRINITY_PROJECT_ROOT` und,
  bei BrainVault-Projekten, `TRINITY_BRAINVAULT_ROOT`.
- Mail-Auftraege sind fuer Pi erlaubt, aber sicher begrenzt: Standard ist das
  Vorbereiten von Entwuerfen. Senden, Loeschen oder Verschieben von Mails bleibt
  an eine konkrete explizite Nutzerfreigabe gebunden.
- Pi ist in neuen Default-Konfigurationen wie Codex fuer Agentenbuilder und
  Agentenausfuehrung aktiviert.

## Validierung

- `python3 -m py_compile agents/pi_agent/script.py core/configuration.py`
- `PYTHONPATH="$PWD/core:$PWD" python3 -m pytest -q tests/test_pi_agent.py`
- Voller versionierter Testlauf: `PYTHONPATH="$PWD/core:$PWD" python3 -m pytest -q $(git ls-files 'tests/test*.py')`
- Live-Smoke direkt im BrainVault: Pi erkannte `AGENTS.md` und `.agents` ohne
  Dateiänderungen.
- Live-Smoke ueber den Trinity-Pi-Adapter: Pi erkannte `AGENTS.md`, `.agents`
  und die Mail-Agentenordner mit relativen Pfaden.
