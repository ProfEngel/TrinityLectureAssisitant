# Trinity v0.15.1 - Gemeinsame Harness-Einstellungen

## Neu

- ClassicUI ersetzt die getrennten Codex-, Pi- und OpenCode-Reiter durch
  einen gemeinsamen Reiter `Harnesses`.
- Jedes Harness kann dort fuer drei Rollen konfiguriert werden:
  Agentenbuilder, harte komplexe Faelle und Ausfuehrung der Agenten.
- Unterhalb der Harness-Konfiguration gibt es eine Agenten-Matrix. Pro
  Trinity-Agent kann ausgewaehlt werden, ob Codex, Pi oder OpenCode ihn
  ausfuehren darf.
- Jeder Harness-Block besitzt einen Testbutton, der die lokale Anbindung
  prueft. Codex und OpenCode werden per `--version` getestet, Pi wird als
  generischer Wrapper auf Existenz geprueft.
- WebUI-Einstellungen buendeln Codex, Pi und OpenCode ebenfalls unter
  `Agenten-Frameworks`, erlauben Rollen/Agenten-Zuordnung ueber JSON-Felder
  und enthalten dieselben harmlosen Anbindungstests.

## Migration und Update-Sicherheit

- Alte Konfigurationen ohne `harness_routing` werden automatisch migriert:
  aktivierte Codex-, OpenCode- und Pi-Schalter setzen sinnvolle Startrollen.
- Bereits vorhandene `harness_routing`-Rollen werden beim Laden nicht
  ueberschrieben. Manuelle Rollen- oder Matrixentscheidungen bleiben erhalten.
- macOS- und Windows-Installer sichern beim Update nun auch `TrinityRuntime`
  und stellen diesen Ordner wieder her.
- Nach der Installation wird `trinity control-plane init` idempotent ausgefuehrt,
  damit neue Runtime-/Vault-Strukturen ergaenzt werden, ohne bestehende Daten
  zu verlieren.

## Dokumentation

- README, Onboarding und Agenten-Oekosystem beschreiben den gemeinsamen
  Einstellungsort `Einstellungen -> Harnesses`.
- Die Dokumentation erklaert, dass weitere Frameworks wie Claude Code spaeter
  nach demselben Muster ergaenzt werden koennen.

## Tests

- Syntaxpruefung fuer ClassicUI/WebUI/Konfiguration.
