# Trinity v0.16.45 - Local media routing and G2 payload delivery

## Changes

- Normal image-generation requests now use the local ComfyUI agent by default.
- fal.ai is selected only when the user explicitly requests an external image or names fal.ai.
- Existing image, audio, and video HTML payloads are exposed as regular authenticated media attachments for Companion and Even Realities G2 clients.
- Lecture heartbeat analysis can identify a relevant technical term and publish a concise definition bubble.
- Heartbeat analysis also includes recent G2 and chat user turns instead of relying solely on the desktop microphone transcript.

## Examples

- `Trinity, erstelle ein Schaubild zur Spieltheorie.` uses local ComfyUI.
- `Trinity, erstelle ein externes Schaubild zur Spieltheorie.` uses fal.ai.

## Compatibility

- The same routing and bridge implementation is used on macOS and Windows 11.
- Existing clients remain compatible. Updating Trinity Desktop is required for the new routing and payload attachment behavior.
- Companion and G2 media access remains protected by the configured Bridge bearer token.

## Verification

- Local and explicit external image routing covered by automated tests.
- HTML image payload conversion and authenticated media URL delivery covered by bridge tests.
- Existing bridge, G2 audio, session, and workspace behavior checked by the project test suite.
