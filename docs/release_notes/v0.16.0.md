# Trinity v0.16.0 - BrainVault-Agentenbasis

## Neu

- Externe Fachagenten werden direkt unter `BrainVault/.agents/<bereich>/<agent-id>/`
  als BrainVault-Draft angelegt.
- Jeder BrainVault-Agent erhaelt `agent.yaml`, `SKILL.md` und `README.md`.
- `BrainVault/.catalog/agent_catalog.json` und `AGENT_CATALOG.md` werden aus
  den `agent.yaml`-Dateien generiert.
- Neues CLI-Werkzeug `agentctl`:
  - `agentctl init`
  - `agentctl create <bereich> <agent-id>`
  - `agentctl list`
  - `agentctl inspect <agent-id>`
  - `agentctl validate <agent-id>`
  - `agentctl catalog build`
  - `agentctl audit <suchpfad>`
- Trinitys Agentenkatalog zeigt BrainVault-Agenten getrennt mit `tier=brainvault`
  und `source=brainvault`.
- Der Agentenbuilder importiert externe Agentenordner nun als BrainVault-Draft
  statt dauerhaft als `skills/staging`-Agent.
- Die Control Plane initialisiert das BrainVault-Layout mit `.agents`, `.ai`,
  `.catalog`, `AGENTS.md` und `CLAUDE.md`.

## Kompatibilitaet

- Trinity-interne Agenten bleiben im Trinity-Repository.
- Das alte `shared/personal/staging`-System bleibt fuer bestehende Trinity-Skills
  und Altdaten erhalten, ist aber nicht mehr die kanonische externe
  Agentenarchitektur.
- Bestehende Job-/Builder-UI bleibt kompatibel; interne Rueckgabefelder wie
  `staging_path` koennen weiterhin verwendet werden, zeigen aber bei neuen
  externen Agenten auf den BrainVault-Draft-Ordner.

## Sicherheit

- Keine automatische Loeschung oder Migration vorhandener BrainVault-,
  CampusHub- oder Ideaverse-Ordner.
- Vor echten Konsolidierungen sollte `agentctl audit ...` ausgefuehrt und der
  erzeugte `BRAINVAULT_AGENT_AUDIT.md` geprueft werden.
- `.ai/env/*.env` und `.ai/secrets/*` werden durch `.ai/.gitignore`
  ausgeschlossen.
