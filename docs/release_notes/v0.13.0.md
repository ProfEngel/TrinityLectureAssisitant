# Trinity v0.13.0 - Server, Clients und getrennte Nutzerbereiche

## Neu

- `trinity server --auth` startet Trinity als Headless-Server mit passwortgeschuetzter WebUI.
- Beim ersten Zugriff wird ein Admin-Account angelegt. Weitere Accounts koennen nur durch einen Admin angelegt werden.
- Passwoerter werden mit PBKDF2-SHA256 und individuellem Salt gespeichert. Bearer-Sitzungstokens liegen ausschliesslich im Arbeitsspeicher des Servers.
- Pro Account werden Chatverlauf, Datei-Uploads und SQLite-Memory unter `memory/users/<user-id>/` getrennt gespeichert.
- `trinity client login --url ...` verbindet eine macOS- oder Windows-Installation mit einem entfernten Trinity-Server. Die ClassicUI arbeitet danach als Server-Client und uebertraegt auch Anlagen.
- `trinity client status` prueft die Verbindung; `trinity client logout` schaltet wieder auf lokalen Betrieb um.
- Ein angemeldeter Admin kann mit `trinity client add-user` weitere Accounts anlegen.
- Die grafischen Einstellungen enthalten den Bereich **Trinity-Server Client** fuer URL, Nutzername, Token und Aktivierung.

## Kompatibilitaet

- Lokale macOS- und Windows-Installationen bleiben standardmaessig Einzelplatzinstallationen.
- Der vorhandene Bearer-Token-Modus fuer iPhone/iPad-Companion bleibt erhalten.
- Der Server arbeitet absichtlich seriell, damit lokale Modelle und Agenten stabil bleiben; die Datenraeume der Nutzer sind dennoch getrennt.
