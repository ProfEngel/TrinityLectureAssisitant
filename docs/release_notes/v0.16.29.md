# v0.16.29 - Queue-based UI chat and session-safe bridge replies

## Highlights

- ClassicUI, iPad and iPhone now enqueue chat requests through the Bridge instead of overwriting a single `cmd.txt` command file.
- The transcriber runtimes consume queued chat requests one by one while keeping the legacy `cmd.txt` fallback for older local flows.
- Bridge event filtering is stricter for `session_id`, so clients working in different sessions no longer see unscoped events from another active session.
- Dynamic skill detection is guarded: if an external skill or BrainVault/iCloud path raises during `can_handle`, Trinity logs the problem and continues to the normal LLM answer path.
- Pi/BrainVault path inspection now tolerates unreadable directories instead of aborting the whole chat routing path.

## Companion impact

- Session and workspace switch messages are transient in the Companion UI and fade instead of staying over the chat.
- Companion polling no longer advances the active session cursor based only on events from other sessions.
- Multiple clients can send into different sessions without blocking each other behind a stale command file.
