# Trinity Assistant v0.15.4

## Highlights

- Agentenbuilder-Auftraege laufen jetzt als sichtbare Trinity-Jobs mit
  Quality-Gates.
- Agenten erstellen, importieren oder erweitern erzeugt echte Staging-Artefakte
  statt nur einen Plantext.
- Optional koennen Codex, Pi oder OpenCode als Harness-Feedback in den
  Builder-Loop einbezogen werden, wenn sie in den Einstellungen aktiviert sind.
- Die Onboarding-Dokumentation wurde von persoenlichen Beispielpfaden und Namen
  auf neutrale Platzhalter umgestellt.

## Neuer Builder-Loop

Bei Auftraegen wie:

```text
Trinity, hol Dir diesen Agenten "/pfad/zum/Agentenordner" und mache ihn mit Pi
fuer Trinity lauffaehig.
```

legt Trinity einen Staging-Skill unter `skills/staging/` an und schreibt dort:

- `manifest.json`
- `BUILDER_PLAN.md`
- `VALIDATION_REPORT.md`
- optional `HARNESS_REPORT.md`
- Import- oder Builder-README
- Platzhalter-Runner und Smoke-Test

Der Fortschritt ist sichtbar ueber:

```bash
trinity jobs list
trinity jobs show JOB_ID
```

## Sicherheitsgrenze

Der Loop darf vorbereiten, testen und berichten. Er promoted einen Agenten nicht
automatisch nach `skills/personal` oder `skills/shared`. Dafuer bleibt eine
explizite `activate_skill`-Freigabe notwendig.

## Tests

Getestet mit:

```bash
PYTHONPATH="$PWD/core:$PWD" python3 -m pytest -q $(git ls-files 'tests/*.py')
```
